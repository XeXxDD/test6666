## SC2 Editor Dark Theme Activator — краткий контекст

Цель: найти внутреннее состояние SC2Editor_x64.exe, из-за которого текст параметра/кнопки `Variable` становится зелёным (`0xA000`), а затем использовать это для тёмной темы. Работаем экспериментами: одно изменение → билд → лог → вывод.

### Что уже установлено

* `Variable`: CtlID `471` (`0x1D7`)
* `Value`: CtlID `473` (`0x1D9`)
* SC2 использует owner-draw (`WM_DRAWITEM`).
* Цвета:

  * красный `0x804040` — обычное состояние без начального значения;
  * синий `0xFF` — состояние с начальным значением;
  * зелёный `0xA000` — редактор автоматически выделяет/выбирает параметр;
  * розовый — физический mouse-down/pressed, это НЕ нужное нам semantic selected state.
* `ODS_SELECTED` зелёный цвет не объясняет: при одинаковом `itemState` цвет может быть синим или зелёным.
* Родительский HWND и обычное состояние GDI также не являются источником переключения цвета.
* Через `SetTextColor` уже удалось стабильно поймать semantic colors.

### Найденный код

SC2 base:
`00007FF635770000`

SetTextColor caller:
`00007FF6376BEDC8`
RVA:
`0x1F4EDC8`

Вокруг него найден следующий код:

```text
40 55 53 56 57 41 54 41 55 41 56 41 57 ...
48 8B FA              ; mov rdi,rdx
4C 8B 3A              ; mov r15,[rdx]
48 8B F1              ; mov rsi,rcx
8B 81 B0 00 00 00     ; [rcx+0xB0]
8B 81 B8 00 00 00     ; [rcx+0xB8]
8B 4A 18              ; [rdx+0x18]
8B 86 B4 00 00 00     ; [rsi+0xB4]
...
49 8B CF              ; mov r9,rdi
...
FF 15 18 C6 59 01     ; indirect call
8B 4F 0C
8B 4F 14
8B 4F 08
8B 4F 10
```

То есть перед вызовом цвета функция использует `RCX` и `RDX`, читая поля объекта/контекста по смещениям `+B0`, `+B8`, `+B4`, `+18`.

### V75

SetTextColor hook расширен до x64 ABI и логирует:

```text
color
arg3
arg4
```

Для зелёного и красного значения `arg3/arg4` различаются, но пока источник semantic state не установлен.

### V77

Добавлен дамп машинного кода вокруг caller.

Важное наблюдение:

`caller = +0x1F4EDC8`

В дампе начало большой функции находится примерно за `0x98` байт до caller, то есть около:

`SC2 + 0x1F4ED30`

### V78/V79

V78 пытался поставить Detours hook на:

`SC2 + 0x1F4ED38`

Адрес:
`00007FF6376BED38`

`DetourAttach` дал error `87`.

V79 сделал диагностическую проверку без hook.

Лог показал:

```text
[V79] INTERNAL target=00007FF6376BED34 rva=0x1F4ED34
[V79] ENTRY BYTES:
57 41 54 41 55 41 56 41 57 48 8D AC 24 ...
```

Но это важная поправка: `+0x1F4ED34` также не доказан как настоящий entry point. Это место начинается с части пролога, тогда как полный обнаруженный пролог:

```text
40 55 53 56 57 41 54 41 55 41 56 41 57
```

находится примерно с `+0x1F4ED30`.

Поэтому сейчас НЕ надо вслепую считать `0x1F4ED34` правильным entry.

### Последний V80

Лог:
`https://pastebin.com/NwzSFbXU`

V78 написал:

```text
[V78] SetTextColor + internal color function hooks installed.
```

Но ни одного:

```text
[V78] INTERNAL_ENTRY
```

не появилось.

Следовательно, установленный V78 hook не попал в реально исполняемый путь либо адрес не является настоящей точкой входа.

### Текущее состояние

Не менять пока адрес наугад.

Следующий правильный шаг — точно определить **настоящий entry point функции**, а не выбирать `0x1F4ED30/34/38` по расположению байтов.

Лучший диагностический способ — использовать Windows `RtlLookupFunctionEntry` для адреса `caller=SC2+0x1F4EDC8` и получить:

* `BeginAddress`
* `EndAddress`
* соответствующий RVA функции.

Это позволит точно узнать начало функции без Detours и без `__try/__except`.

После этого уже ставить V78 hook именно на возвращённый `BeginAddress` и смотреть `RCX/RDX`.

### Важные ограничения

* Не возвращаться к старым V69/V70 с поиском IAT/hex memory.
* Не использовать hardware breakpoints/external debugger.
* Не расширять исследование DRAWITEM — нужный цвет уже успешно пойман через `SetTextColor`.
* Не использовать `HwndToString`; такой функции нет.
* `Log()` принимает одну `std::string`.
* Предпочтительно давать точные инструкции вида: «найди X → внутри него найди Y → сразу после Y вставь Z».
* Следующий эксперимент должен быть диагностическим и минимальным.
